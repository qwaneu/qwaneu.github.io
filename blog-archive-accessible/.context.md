From README.md, sections "IN PROGRESS" and "Styling": "Pagina van lijst van blog entries accessible maken" and "#blog pagina accessible maken (zie ook 'grid' to do)".

Where: _layouts/blog-index.html (tag filtering via CSS `:target`), blog.html, blog-by-tag.html, _sass/_blog.scss.

What is wrong today: the layout builds an inline <style> block with a per-tag `:target` rule, a `display:none` default, and a pseudo-element with a 9999px negative margin. Tag filtering is therefore pure CSS state: the tag links do not navigate to real documents, and anything that does not implement `:target` sees an empty archive. The selector is also built by string join (`#tag-{{ tag_names | join: ", #tag-" }}`), which breaks as soon as a tag name contains a character that needs escaping.

Goal: a blog archive where every tag link is a real URL that returns a real page or a real anchor, the filtered state is visible in the URL, and the reading order makes sense without CSS. Jekyll can do this with generated tag pages from `site.tags` instead of the :target trick. Decide which design you want before writing code; the :target approach is not salvageable into something accessible without JS, and adding JS to fix CSS is the wrong direction.
