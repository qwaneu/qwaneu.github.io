Queued by decision Q2/B on 2026-10-31. Deliberately AFTER the gate exists and after the first layout work, so a regression cannot be attributed to two things at once.

Why: GitHub Pages pins Jekyll 3.10.0 (github-pages 232, released 2024-08) and has not moved in 14 months. Local Jekyll is 4.4.1. Staying on Pages means staying on 3.10 forever. Moving to Actions means the pinned gem set stops being the build of record and CI becomes it.

Scope: new workflow that builds with jekyll 4.4.1, flips Pages source to Actions, and runs the same gate the harness runs locally (single command, same container). Migration items to check: jekyll-sass-converter 1.5.2 -> 2.x (sass syntax differences), kramdown 2.3/2.4 -> 2.4, the `plugins:` list (_config.yml:59-60, currently jekyll-redirect-from), the vestigial `assets:` block from jekyll-assets, and `_config.yml`'s `exclude` list.

Clickops constraint (stated by the human): they dislike clickops. Use `gh api` / `POST /repos/{owner}/{repo}/pages` with `build_type: workflow` to flip the source from a script, and record the command in this yak when it is used. The only manual step should be the initial credential.

Done when: a push to master builds on Actions, the build is reproducible from the container, the gate runs in CI, and `qwan.eu` is served by the Actions deployment. Rollback path recorded (flip build_type back to `legacy` and the old Pages build resumes).
