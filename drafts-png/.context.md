Found 2026-10-31 while verifying the new container build (gate-ghpages-232).

Symptom, reproducible: `bundle exec jekyll serve --drafts` prints
`Error: could not read file /site/_drafts/frictionless.png: invalid byte sequence in UTF-8`
and carries on. Jekyll treats every file under _drafts/ as a draft post, so the
PNG is read as text. A plain `jekyll build` (no --drafts) is unaffected, which is
why nobody noticed.

Where: _drafts/frictionless.png (referenced by _drafts/frictionless-summary.md).
Possible fixes: move the image to attachments/ and update the markdown reference
(preferred: _drafts/ then holds only text), or add the path to `exclude` in
_config.yml if that works for drafts (verify; exclude may not apply to drafts).

Why it belongs here and not in a11y-defects: it is a build-log defect. The
container build is now the gate's only verification, and "zero defects" means a
red or error line in that log is a finding, not noise.

Done when: `jekyll serve --drafts` produces no error lines, and the draft that
uses the image still renders it.
