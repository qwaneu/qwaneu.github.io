Where: _includes/header_clean.html:30 -> `<a class="ribbon__element" >{{page.title}}</a>`

Why it matters: an <a> with no href is not a link. It is not focusable and gets no link role, so the breadcrumb trail silently loses its last element for keyboard and screen reader users. This include is used by every post (_layouts/post.html) and by the accessible layouts, so the defect is site-wide.

Likely fix: the current page is not a link. Render it as a <span aria-current="page"> (or plain text) instead of an anchor, and keep the preceding crumbs as links. Check the ribbon's CSS in _sass/_breadcrumbs.scss so styling survives.

Done when: rendered HTML contains no anchor without href, and the crumb still reads as "Home > Blog > <title>" to a screen reader at 390/768/1440.
