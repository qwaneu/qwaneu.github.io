Where: _layouts/post.html:10-11 -> `<p class="post-meta">` followed by `<div>` children (and more divs before `</p>`).

Why it matters: a <p> cannot contain <div>. Browsers reparent it while parsing, so the DOM assistive tech sees is not the DOM the template pretends to emit. It affects every post. This is exactly what an HTML parse check catches, which is why the gate proposes one (gate-a11y-ratchet).

Likely fix: make the container a <div class="post-meta"> (or a <footer>), keep the inner spans, and drop the stray `.entry-title` class that is currently appended to the header class list (_layouts/post.html:8: `class="post-header .entry-title"` — the leading dot makes it a literal class name).
