From README.md, sections "IN PROGRESS" and "Styling": "Pagina van lijst van blog entries accessible maken" and "#blog pagina accessible maken (zie ook 'grid' to do)".

Where: _layouts/blog-index.html (tag filtering via CSS `:target`), blog.html, blog-by-tag.html, _sass/_blog.scss.

What is wrong today: the layout builds an enormous inline <style> block with a per-tag `:target` rule and a 9999px-negative-margin pseudo-element, plus a `display:none` default. Filtering by tag is therefore invisible to anything that does not implement :target — including most screen readers' "links" list, since the tag links do not navigate to real documents. The markup also lays out violations out of band: `#tag-{{ tag_names | join: ", #tag-" }}` builds a selector from a string join, which breaks as soon as a tag name contains a character that needs escaping.

Goal: a blog archive where every tag link is a real URL that returns a real page or a real anchor, the filtered state is visible in the URL, and the reading order makes sense without CSS. The static site can do this with tag pages (Jekyll's `site.tags` + permalink per tag) instead of the :target trick. Decide which of the two designs you want before writing code; the :target approach is not salvageable into something accessible without JS, and adding JS to fix CSS is the wrong direction.

Also covers: the arrow/link affordances in the list, and heading order on the page.
